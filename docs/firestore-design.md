# RehearseAI Firestore Design

RehearseAI uses Firestore as the primary application database for users, sessions, reports, analytics, billing metadata, entitlements, and admin operations.

Backend services that use Firebase Admin SDK or Google service-account credentials bypass Firestore security rules. Frontend clients are restricted by `firestore.rules`.

## Top-Level Collections

- `users/{uid}`
- `sessions/{sessionId}`
- `sessions/{sessionId}/messages/{messageId}`
- `reports/{reportId}`
- `analytics/{analyticsId}`
- `reasoningTrees/{treeId}`
- `historicalPerformance/{uid}`
- `plans/{planId}`
- `userEntitlements/{uid}`
- `billing_customers/{uid}`
- `billing_subscriptions/{subscriptionId}`
- `billing_checkouts/{checkoutId}`
- `adminLogs/{logId}`
- `featureUsage/{usageId}`
- `contact_submissions/{id}`

## users/{uid}

Stores Firebase-authenticated user profiles.

Fields:
- `uid: string`
- `email: string`
- `displayName: string`
- `photoURL: string | null`
- `role: "user" | "admin"`
- `planId: string`
- `planName: string`
- `status: "active" | "disabled"`
- `createdAt: timestamp`
- `updatedAt: timestamp`
- `lastLoginAt: timestamp`

Rules:
- Users can read their own profile.
- Users can update safe profile fields only.
- Users cannot change `role`, `planId`, `planName`, or `status`.
- Admins can read/write all users.

## sessions/{sessionId}

Stores one cognitive performance training session.

Fields:
- `sessionId: string`
- `userId: string`
- `practiceType: string`
- `difficulty: string`
- `topic: string`
- `context: string`
- `goal: string`
- `optionalNotes: string`
- `status: "active" | "completed" | "archived"`
- `turnCount: number`
- `createdAt: timestamp`
- `completedAt: timestamp | null`
- `updatedAt: timestamp`

Rules:
- Users can create sessions where `userId == request.auth.uid`.
- Users can read their own sessions.
- Users can update their own active sessions.
- Users cannot change `userId` after creation.
- Admins can read all sessions.

## sessions/{sessionId}/messages/{messageId}

Stores roleplay conversation turns.

Fields:
- `messageId: string`
- `sessionId: string`
- `userId: string`
- `role: "user" | "ai"`
- `content: string`
- `createdAt: timestamp`
- `metrics: map optional`

Rules:
- Users can read messages only for their own session.
- Users can create only `role == "user"` messages for their own session.
- Users cannot write `role == "ai"` messages directly.
- Backend/Admin SDK can create AI messages because backend writes bypass rules.

Rules:
- Users can read their own reports.

- Backend/admin creates reports.

- `pressureHistory: array`

Rules:
- Users can read their own historical performance.

## plans/{planId}

Stores plan templates controlled by admin.

Fields:
- `planId: string`
- `name: string`
- `description: string`
- `priceMonthly: number`
- `priceYearly: number`
- `currency: string`
- `paddleProductId: string`
- `paddleMonthlyPriceId: string`
- `paddleYearlyPriceId: string`
- `isActive: boolean`
- `sortOrder: number`
- `entitlements: map`
- `createdAt: timestamp`
- `updatedAt: timestamp`

Rules:
- Signed-in users can read active plans.
- Admins can create/update/delete plans.

Default plans:
- `free`
- `pro`
- `coach`

## userEntitlements/{uid}

Stores the effective plan and access controls for a user.

Fields:
- `uid: string`
- `planId: string`
- `planName: string`
- `status: "active" | "trialing" | "past_due" | "cancelled"`
- `source: "manual" | "paddle" | "trial" | "admin"`
- `entitlements: map`
- `overrides: map`
- `trialEndsAt: timestamp | null`
- `subscriptionId: string | null`
- `paddleCustomerId: string | null`
- `updatedAt: timestamp`

Rules:
- Users can read their own entitlement.
- Users cannot write their own entitlement.
- Backend/admin writes entitlements.

## contact_submissions/{id}

Stores messages submitted through `/contact`.

Fields:
- `id: string`
- `name: string`
- `email: string`
- `topic: string`
- `message: string`
- `createdAt: timestamp`

Rules:
- Users do not write this collection directly from the frontend.
- FastAPI stores submissions through backend credentials.
- Admins can read, update, or delete contact submissions.

## Standard Entitlement Map

These fields live under `plans/{planId}.entitlements` and `userEntitlements/{uid}.entitlements`.

- `maxSessionsPerMonth: number | "unlimited"`
- `maxMessagesPerSession: number`
- `maxSessionMinutes: number`
- `allowBrutalMode: boolean`
- `allowChallengeMode: boolean`
- `allowVoiceMode: boolean`
- `allowAdvancedAnalytics: boolean`
- `allowDecisionTree: boolean`
- `allowHistoricalTrends: boolean`
- `allowBenchmarking: boolean`
- `allowShareableReports: boolean`
- `allowReportExport: boolean`
- `allowSessionReplay: boolean`
- `allowLongitudinalMemory: boolean`
- `allowCustomPersonas: boolean`
- `reportDepth: "basic" | "advanced" | "coach"`
- `historyRetentionDays: number | "unlimited"`
- `monthlyGeminiTokenLimit: number`

Entitlements should be checked before:
- Creating sessions.
- Selecting Brutal mode.
- Generating advanced analytics.
- Generating decision trees.
- Reading historical reports.
- Exporting or sharing reports.

## Seed Default Plans

From the repo root:

```bash
cd backend
source venv/bin/activate
python scripts/seed_firestore.py
```

## Create First Admin

Set these environment variables before running the seed script:

```bash
FIRST_ADMIN_EMAIL=you@example.com
FIRST_ADMIN_UID=YOUR_FIREBASE_UID
python scripts/seed_firestore.py
```

If `FIRST_ADMIN_UID` is provided, the seed script:
- Sets `users/{uid}.role = admin`.
- Creates or updates `users/{uid}`.
- Assigns the `coach` plan in `userEntitlements/{uid}`.
- Writes an `adminLogs` entry.

## Security Notes

- Never expose service account keys to the frontend.
- Backend Admin SDK writes bypass Firestore rules.
- Frontend reads/writes must be restricted by `firestore.rules`.
- Before production, enforce admin access on FastAPI endpoints using Firebase Admin ID token verification and preferably custom claims.
